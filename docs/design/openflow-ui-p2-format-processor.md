# OpenFlow UI-P2 格式处理工作区设计

## 目标与边界

UI-P2 在 `06ccd141515601f1ca5099a265d801bb64353532` 的 UI-P1 基线上重排格式处理页面表现层。实现继续复用 `PageHeader`、现有 Mantine Theme 和 `openFlowTokens`；文件识别、队列规则、处理参数、状态来源、IPC 调用、Sharp/FFmpeg、导出命名及文件安全逻辑均保持不变。

## 信息架构

页面保持三个层级：

1. 一级标题：复用全局 `PageHeader`。
2. 文件工作区：空拖放态或文件队列，状态和文件元信息均在同一容器内。
3. 参数面板：处理动作流、尺寸、质量、格式、导出路径以及正常文档流中的开始按钮。

文件队列新增一致的类型图标、文件大小、待处理/处理中/完成/失败状态和明确错误信息。长文件名与长路径使用可收缩布局，保留完整 `title` 信息，不撑破页面。

## 桌面双栏

- 断点以上使用稳定双栏，间距为 16px。
- 参数面板固定为 320px，主工作区使用剩余宽度；两列均设置正确的 `min-width: 0` 和 `min-height: 0`。
- 内容最大宽度为 1320px并居中，最大化后拖放区不会无限拉伸。
- 1080×640 时实测主工作区 612px、参数面板 320px；内容未覆盖且无横向滚动。

## 紧凑单列

在 `max-width: 820px` 时，工作区改为单列纵向流程：文件区在前、参数面板在后。`.format-layout` 是唯一纵向滚动容器，使用 `overflow-y: auto` 和 `overflow-x: hidden`；文件队列、参数面板与开始按钮均处于正常文档流。

760×520 外窗下，空拖放区压缩到 188px 的可操作高度，工作区整体仍可滚动到参数面板和开始按钮。没有 fixed 或覆盖式操作条，也未隐藏任何字段。

## 拖放与状态

- 空状态：中性虚线边框、上传图标和同类型提示。
- drag-active：品牌蓝描边与浅蓝语义背景。
- 已添加：显示类型、文件名、大小和待处理状态。
- 处理中：加载指示和橙色状态；开始按钮保持禁用。
- 按钮 Loader 必须以开始处理按钮自身为定位上下文；页面专用按钮类需要保留定位上下文，不能用 `position: static` 覆盖 Mantine 的加载层包含块。
- 成功：统一绿色状态，并显示输出路径。
- 失败：统一红色状态，并在列表项中显示完整错误。
- disabled：继续由原有 `files.length === 0` 与 `isProcessing` 条件控制。

## 参数面板

参数面板保留原字段、顺序、默认值和范围：调整分辨率、输出质量、格式转换、动作文件夹名、自定义导出目录。字段以标题、控件和说明三级排列，普通容器使用中性背景及 1px 描边，不增加卡片阴影。自定义路径可省略显示，但完整路径保留在 `title` 中。

## 可访问性与主题

- 交互控件沿用 Mantine 的 `focus-visible`，删除文件按钮补充具体文件名的 `aria-label`。
- Tab/Shift+Tab 可遍历导航、表单和主要动作；Enter/Space 可激活原有入口。
- 浅色和深色均只使用现有语义变量；蓝色用于主操作、选中和焦点，绿色/橙色/红色分别用于成功/处理中/失败。
- 100%、125%、150% Chromium zoom 下仍保持单列滚动与零横向溢出。

## 非目标

本阶段没有修改其它一级页面内部布局、主进程、preload、shared 契约、IPC、Sharp/FFmpeg、BrowserWindow 尺寸、依赖或配置结构。
