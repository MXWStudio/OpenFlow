# OpenFlow UI-P4 日常处理工作区设计说明

## 目标与非目标

UI-P4 在既有功能和数据状态不变的前提下，将日常处理页整理成紧凑、可扫描、可在 760×520 使用的生产力工作区。目标是统一信息层级、消除操作区覆盖、明确校验与重命名关系，并保持浅色、深色和高缩放可用。

本阶段不修改需求解析、目录创建、素材识别或去重、命名模板、尺寸规则、校验、重命名、同名保护、配置、IPC、BrowserWindow 或任何主进程逻辑。

## 改造前问题

- 760×520 实际客户区约 744×481，绝对定位的底部操作栏覆盖命名卡片和滚动内容。
- 低宽度规则在 720px 才生效，无法覆盖 744px 客户区，页面仍按桌面网格组织。
- 流程、需求、命名和状态卡片争抢一级层级，阅读顺序不清楚。
- 30px 状态标题、70px 状态图标、较重字重和多层阴影使页面密度偏低。
- 最大化后内容未限制宽度，工作区横向拉伸。
- 目录删除控件缺少具体目录名，长路径仅截断但没有完整信息入口。

## 四阶段信息架构

页面仍使用既有状态形成四阶段概览，不新增或推测完成状态：

1. 今日需求：由 `projectsCount > 0` 表示已有需求。
2. 项目目录：沿用既有 `projectsCount > 0` 状态。
3. 上传素材：由 `folderPaths.length > 0` 表示已有素材目录。
4. 校验处理：由 `hasValidated || canRename` 表示已校验或可以重命名。

概览只用于定位，不替代任何业务反馈。具体异常、缺失、通过和重命名状态仍来自既有校验与批处理结果。

## 桌面布局

内容区最大宽度为 1280px，并在页面中居中。桌面保留左侧准备区和右侧工作区：左侧包含阶段概览、需求导入和命名准备；右侧包含状态、素材与尺寸、校验详情和操作区。所有 Flex 子项设置 `min-width: 0`，卡片使用语义表面、1px 描边和无默认大阴影。

## 760×520 单列与滚动

在 820px 及以下，Daily 工作区切换为单列。阶段概览压缩为四列；需求操作为两列；素材与尺寸改为上下排列。页面仅使用 `.daily-scroll` 作为主纵向滚动容器。校验和重命名操作位于文档流末端，不使用 fixed、absolute 或 sticky，不需要遮挡补偿区。

## 状态与内容规则

- 需求：显示当前需求文件、抓取时间和既有导入/创建入口。
- 目录与素材：每个目录保留名称、完整路径、添加、清空和单项移除入口；重复目录行为仍由原逻辑处理。
- 命名：常规、特殊、自定义选择和全部预览、错误、重试入口保持不变。
- 尺寸：需求尺寸、识别尺寸、横版/方形与竖版手动尺寸全部保留。
- 校验：状态摘要、分组详情、通过项、异常操作和废纸篓入口保持不变。
- 重命名：校验前“开始校验”为主操作；既有状态允许重命名后，“执行重命名”为主操作，重新校验降为次操作。

## 长内容与多目录

项目名、需求名、目录名、路径、文件名和错误详情必须可收缩。目录名和路径使用省略显示并通过 `title` 暴露完整值；命名示例与错误详情允许任意位置换行；表格在自身横向滚动区内展示，不扩大页面宽度。目录删除按钮的可访问名称包含目标目录名。

## 主题与缩放

页面只使用 Mantine 和 OpenFlow 语义变量。浅色与深色使用同一层级结构，不维护页面专用硬编码颜色。100%、125% 和 150% 缩放均遵循 820px 单列规则和唯一主滚动规则；高缩放不会启用覆盖式操作栏。

## 键盘、焦点与可访问性

DOM 顺序与视觉顺序一致：需求、命名准备、状态、素材与尺寸、校验详情、校验和重命名操作。所有既有按钮继续使用原生 Mantine 可聚焦控件；全局 `focus-visible` 轮廓保持生效。校验位于重命名前，禁用的重命名按钮仍保持可读标签，目录删除按钮提供具体名称。

## 严格业务边界

UI-P4 仅调整 `DailyWorkspace.tsx` 的表现结构、Daily 专用 CSS、静态契约测试和本设计/QA 文档。所有 props、事件处理函数、loading/disabled 条件、IPC 参数、通知、配置字段、文件算法和窗口尺寸保持原样。任何需要改变业务条件的发现均应拆分为独立功能任务。
