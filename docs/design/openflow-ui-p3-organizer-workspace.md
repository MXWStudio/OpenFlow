# OpenFlow UI-P3 素材自动整理工作区设计

## 目标与非目标

UI-P3 统一素材自动整理页面的信息层级、密度、主题和紧凑窗口行为。页面继续复用全局 `PageHeader`、Mantine Theme 与 `openFlowTokens`，只调整 Renderer 表现层。

本阶段不改变扫描、格式过滤、游戏名或分辨率识别、转移、同名保护、奇觅目录、撤销、配置持久化、IPC 参数和通知语义，也不修改 BrowserWindow、依赖或其它业务页面内部布局。

## 当前问题

- 系统状态、快捷操作与待整理素材被多层大圆角卡片包裹，层级重复。
- 760×520 使用绝对定位底部操作条，最后内容会被覆盖。
- 视频转移选项使用大面积橙色填充，压过扫描与确认转移。
- 浅色主题仍出现不必要的深色大 Surface。
- 最大化时内容接近全宽，状态文字和操作行被过度拉长。
- 目录、文件名和目标路径缺少一致的收缩规则。

## 信息架构

页面保持三层结构：

1. 全局 `PageHeader`；
2. 状态与快捷操作区；
3. 待整理素材工作区及文档流内操作区。

状态区只说明当前阶段和来源目录；快捷操作区承载来源、目标、视频转移选项与撤销；待整理区承载空态、扫描结果、选择和当前阶段主操作。

## 桌面布局

1080×640 及更宽时，状态与快捷操作使用等宽双栏，待整理素材占下一完整区块。内容列使用 `min-width: 0`，整体最大宽度为 1280px 并居中。卡片只使用 1px 中性描边、8px 圆角和无明显阴影，不再使用大卡片套大面板。

## 760×520 布局与滚动

820px 以下改为单列纵向信息流。`organizer-scroll` 是页面唯一主滚动容器；状态、快捷操作、结果和按钮都在同一文档流中。操作区不得使用 `fixed`、`absolute` 或覆盖式 `sticky`。紧凑布局中按钮组可换行或铺满列宽，最后操作始终能滚动到达。页面和滚动容器均不得出现横向溢出。

## 操作层级和语义颜色

- 就绪或空扫描阶段，“一键扫描”使用品牌蓝主按钮。
- 有可转移文件时，“确认转移”成为品牌蓝主按钮，“一键扫描”降为次级。
- 更改目录、打开目录和撤销使用次级样式；撤销入口保留原事件和结果语义。
- “视频转移-奇觅生成”改为复选选项，复用原布尔状态和切换事件，不使用橙色大按钮。
- 蓝色用于当前主操作和焦点，绿色用于成功，橙色用于处理中或提醒，红色用于失败和危险。

## 状态规则

- 系统就绪：显示来源目录和扫描主操作。
- 空扫描：明确显示没有需要整理的文件，不伪装为错误。
- 扫描中：保留原 loading 状态和扫描说明。
- 扫描结果：显示数量、选择状态、类型、游戏名、分辨率、大小和目标路径。
- 转移中：保留原 loading/disabled 条件和状态说明。
- 转移完成：显示成功状态、整理目录入口和原撤销入口。
- 撤销完成：重新执行原扫描流程，显示安全的当前来源状态。
- 失败：继续使用原通知通道和错误文本，不增加假状态。

## 主题、缩放和字体

页面 Surface、描边、文本、弱背景和焦点全部使用语义 CSS 变量。浅色不硬编码深色卡片，深色不硬编码纯白面板。布局依赖可收缩网格和正常换行，在 100%、125%、150% Chromium 等效缩放下使用同一断点策略。

页面沿用 4px 网格：区块间距 16px，紧凑元素 8px，主要内边距 16px。分区标题为 16/24/600，正文为 14/20，辅助文字为 12/18；主要操作至少 36px，普通控件至少 32px。

## 键盘与焦点

DOM 顺序与视觉顺序一致：打开来源目录、视频选项、更改来源、更改目标、撤销、文件选择、扫描、确认转移。原生 Button 与 Checkbox 保持可识别名称，Tab/Shift+Tab 可遍历，Enter/Space 继续触发原组件行为，既有全局 `focus-visible` 不被覆盖。

## 业务边界

所有状态来源、处理函数、`onClick`、`onChange`、`loading`、`disabled`、IPC 通道、参数和结果处理保持不变。UI-P3 不新增文件操作，不隐藏功能入口，不改变奇觅选项含义，不改变扫描和转移顺序，也不触碰 main、preload、shared、窗口尺寸、依赖和 package-lock。
