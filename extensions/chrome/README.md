# OpenFlow Chrome 扩展

这是 OpenFlow Studio 配套的 Chrome Manifest V3 扩展。Electron 桌面端和扩展在同一个 OpenFlow 仓库中维护，本目录是扩展的唯一源码入口。

## 功能边界

- 在用户主动点击扩展时读取当前标签页。
- 按用户指定的截止日期，从当前已加载的工单列表提取项目名称、任务状态、制作信息、素材尺寸和所需数量。
- 导出 Excel 报表或 `openflow.requirements.v1` JSON。
- JSON 可由 OpenFlow Studio 直接导入，用于建目录、素材校验和重命名。
- 完整抓取会进入扩展本地 Outbox，并通过认证的本机桥自动送达桌面端；桌面未运行时保留并重试。
- 自动记录抓取数量不闭合、详情校验失败和运行异常；桌面端暂不可用时先保留在扩展本地，稍后自动补交。

扩展不直接修改本地素材。桌面程序运行时，扩展通过电脑本机的临时连接读取更新状态并发送完整抓取结果；该连接不能从外网访问，要求固定扩展身份、随机令牌和协议版本匹配。桌面端严格校验、原子落盘并按消息 ID 去重后才返回 ACK。JSON 手工导入继续保留为回退入口。

## 权限

- `activeTab`：只访问用户当前主动使用的标签页。
- `scripting`：按需注入 `content.js` 完成页面提取。
- `downloads`：保存 JSON 和 Excel 文件。
- `storage`：保存扩展设置、最近一次提取结果和等待桌面确认的 Outbox。
- `alarms`：定时确认桌面程序是否准备了新版扩展。
- 仅允许访问 `127.0.0.1`：连接本机正在运行的 OpenFlow Studio，确认扩展更新结果。

后台任务负责更新检查、避开正在提取的页面、重载扩展、刷新本扩展实际使用过的页面，以及重试尚未获得桌面 ACK 的完整抓取结果。

自动诊断只包含版本、时间、数量闭环、错误码和脱敏后的运行现场，不保存或上传完整网页、素材、Cookie、浏览器资料或本机更新令牌。远程批量回传由桌面端负责，扩展本身不增加外网权限。

## 本地加载

1. 打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 选择“加载已解压的扩展程序”。
4. 正式安装用户在 OpenFlow Studio 的“设置中心 → 关于”中点击“打开扩展文件夹”，选择该目录。开发者可选择源码目录 `extensions/chrome`。

首次从旧版迁移时，如 Chrome 中仍保留旧目录加载的扩展，请移除旧项后加载桌面程序提供的固定目录。完成这一次操作后，后续扩展版本会随桌面程序自动同步。

自动送达依赖桌面程序写入的临时连接信息，因此正式使用和联调应加载“设置中心 → 关于”打开的桌面托管扩展目录。直接加载源码目录适合界面开发，但没有桌面运行时连接文件时会把结果留在 Outbox，并继续保留 JSON 手工导入能力。

## 桌面自动接收

1. 抓取完整结束后，扩展生成协议 2 消息并先保存到本地 Outbox。
2. 桌面端完成来源、协议、大小、数量闭环、任务 ID 和尺寸结构校验后原子落盘，再返回与消息 ID 匹配的 ACK。
3. 桌面工作流为空时自动载入今日最新完整抓取；已有需求、素材文件夹或校验结果时必须由用户确认。
4. 桌面未运行、协议不兼容或临时失败时，Outbox 会在浏览器启动、定时检查和抓取结束后重试；未收到 ACK 不删除。

## 按截止日期抓取

1. 在品创工作台打开目标时间范围；扩展会自动向下加载当前筛选范围内的任务卡片。
2. 打开扩展，选择目标截止日期。
3. 点击“按截止日期提取任务”。任务状态可以是未开始、交付中或完成。
4. 核对预览数量后导出 JSON，并在 OpenFlow Studio 中导入。

## 验证

在仓库根目录运行：

```powershell
npm run check:extension
npm test
```

前者检查 Manifest、最小权限、资源引用和 JavaScript 语法；后者还会用桌面端解析器读取扩展契约样例，防止两端格式漂移。

## 产品边界

已废弃的第一代 PySide6 桌面端原型已经被当前 Electron 桌面端取代，不属于当前产品。扩展不是 Git 子模块，也不依赖其他源码仓库。
